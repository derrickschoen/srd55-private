# X50 — command factory, executor, audit, and RPC

Status: done (BUILD-PLAN command execution slice)

## Delivered

- The factory validates and constructs all thirteen variants: ability; four
  slot modes; rules; source config/add/remove; warning acknowledge/delete;
  class; and snapshot restore. Destructive inverse variants require
  character-bound integrity before construction.
- The executor preserves PHP ordering for UUID replay and revision checks,
  rejects cross-character UUID reuse, permits only stale `set_slot` requests
  whose exact owned slot has no intervening audit row, and increments once.
- Each accepted mutation, revision update, grouped reversible audit diff, and
  operation/inverse insert is committed in one synchronous SQLite transaction.
  Any command/audit/operation failure rolls the entire unit back.
- Async HMAC work is completed before entering sqlite-wasm's necessarily
  synchronous transaction. Warning and snapshot application use equivalent
  synchronous executor paths after the factory has validated integrity.
- The typed client and discovered `commands.execute` handler validate the exact
  request envelope and expose revision conflicts with `current_revision`.

followed by the final green runs:

2. Removed revision increment: the persisted/result revision was 0, not 1.
3. Generated an audit UUID per diff: the two stored rows had two groups.
4. Removed the outer transaction: injected audit failure left wisdom/revision
   persisted instead of restoring the exact prior row.
5. Marked replay false: the replay envelope assertion received false.
6. Bypassed replay ownership: another character consumed the stored inverse.
7. Allowed every stale slot: the touched-slot request persisted revision 3.
8. Renamed the handler: Chromium received unknown_method and could not persist.
