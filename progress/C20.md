# C20 — browser catalog JSON import

Status: done (BUILD-PLAN increment 18)

## Delivered

- `src/catalog/catalog-schema.ts` validates one or more browser JSON documents,
  the complete Tier 1 field contract, optional exact-match Tier 2 text, and the
  strict RPC parameter envelope.
- `src/catalog/catalog-normalize.ts` merges duplicate version records,
  publications and pivots; normalizes identity names; and deterministically
  chooses 2024, expanded, then 2014 canonical names.
- `src/catalog/catalog-importer.ts` transactionally upserts stable identities
  and editions, preserves referenced metadata, synchronizes publications/lists/
  tags/attack modes/save abilities, imports optional text, tombstones or
  reactivates imported versions, refreshes retained selections, protects
  user-provenance rows from tombstoning, and rolls dry runs back after computing
  their summary.
- `src/catalog/client.ts` and `src/worker/handlers/catalog.ts` expose the typed
  `catalog.import` client slice and convention-discovered handler without
  registry edits.
- `docs/CATALOG-IMPORT.md` documents the browser schema, merge rules, Tier 2,
  persistence semantics, licensing note, RPC use, diff, and atomicity.
- Added 3 Unit, 4 Integration, and 1 browser test in the owned test files.

   exact persisted counters before its pivot-row assertions; restored.
3. Reference detection was forced false. The reference test failed because
   stored display name/school changed instead of remaining byte-preserved;
   restored.
4. Dry-run rollback was disabled. The Integration test found the imported row
   persisted as inactive instead of active, and the browser test found a
   committed OPFS version instead of `[]`; restored.
5. The outer database transaction was bypassed. The database-error/RPC test
   found 1 identity and 1 version persisted instead of zero; restored.
