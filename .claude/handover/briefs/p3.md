## Scope

1. **`db/schema/party.ts` — `party_document_states`**, registered in
   `db/schema/index.ts` and `db/schema/relations.ts`, with the section 7 field
   list and nothing else: repository identity, observed ref, path, document
   kind, publication ID, local character ID when applicable, last observed
   remote revision, last imported revision, last published local revision,
   last successful refresh time, most recent named observation state. Every
   fact the app cannot prove is a NULLABLE column with no default — no `''`,
   no `0`, no `CURRENT_TIMESTAMP`, no "just now".
2. **The word "token" is a trap in this design and must not reach the
   schema.** Section 7 says "last observed remote token" meaning a
   `RepositoryRevision`; section 6 says "token" meaning a credential. Name
   every column `*_revision`. A grep for `token|secret|password|bearer|authorization`
   over `db/schema/party.ts`, the generated `src/db/schema.sql` party lines,
   and your migration must return nothing. That grep IS the exit criterion
   "no credential column/key exists" — make it a test, not a habit.
3. **Classify the table in `TABLE_SCOPES`** (`src/domain/contracts/tables.ts`)
   — a new table is a compile error (TS1360) until you do. It needs a new
   `TableRole` member; do not file it under a `catalog_*` or `character_*`
   role, because that module's own rule is that the role names what a table
   HOLDS and a borrowed role makes the field lie (see its `catalog_armor`
   comment). All five booleans are `false`. `backupDirect` stays `false` even
   though the table has a `character_id`. In
   `tests/unit/contracts/table-scopes.test.ts` the historical literals are an
   ORACLE — do not edit them; if a delta is needed it is written as an
   explicit addition list, exactly as `SNAPSHOT_ADDITIONS` already is.
4. **Branded `PartyPublicationId`** in `src/domain/ids.ts` alongside the
   existing brands — a branded string, minted randomly at first publish
   (section 3), never derived from a character ID, a name, or a path. A
   `CharacterId` must not be assignable to it and vice versa; prove that with
   a type probe (`tests/unit/catalog/content-identity.test.ts` is the
   `expectTypeOf` precedent in this tree).
5. **`src/worker/handlers/party.ts` + `src/party/client.ts`** — read/write of
   observation rows only. The handler module is auto-discovered
   (`src/worker/registry.ts:109`, `import.meta.glob('./handlers/**/*.ts')`);
   you do not edit a registry, but you DO extend whatever inventory assertion
   names the RPC surface. `src/backup/client.ts:8-39` and
   `src/worker/handlers/backup.ts:75-86` are the shape precedent. No
   credential crosses this RPC, because none exists to cross it.
6. **The read model reports, it does not rule** (section 7's closing
   paragraph, D138). No character fact, sheet number, name, or list entry may
   be read from `party_document_states`. Publishing state is a projection OVER
   the character's revision, not a second revision authority; recording a row
   never mutates a character; importing a clone (D62) never inherits a
   publication binding from the document it came from.
7. **Observation states are a closed union**, spelled exactly as section 7
   spells them: `Never published`, `Unpublished local changes`, `Published at
   revision N from this device`, `Published; refresh required before another
   publish`, `No longer published`, `Never refreshed`, plus the distinct
   `Last refreshed successfully` / `Latest refresh attempt` pair. Exhaustive
   dispatch, no `default:` arm, no `any`. A failed or partial refresh never
   advances the success time — that is the section 9 partial-refresh row and
   it is a P3 storage rule, not a P4 UI rule.
8. **Regenerate the derived artifacts** with the sanctioned generators
   (`npm run db:schema`, `npm run db:contracts`) and hand-review the diff.
   Those are code generators; they are not licence to regenerate any
   expectation. Confirm `tests/unit/db/schema-signature.test.ts`,
   `tests/unit/db/candidate-audit.test.ts`, `tests/unit/schema*.test.ts`,
   `tests/unit/contracts/*`, `tests/integration/backup/round-trip.test.ts`
   and `tests/integration/sharing/column-portability.test.ts` all go green
   WITHOUT the new table appearing in any backup, share or snapshot set.

## Negative controls — one per load-bearing assertion, exact failing test name

- **PARTY-INDEX-NO-CREDENTIAL-COLUMN** — add a `credential`/`token` TEXT column
  to `party_document_states` (and separately, import a credential-shaped module
  from `db/schema/party.ts`, `src/worker/handlers/party.ts` or
  `src/party/client.ts`): the schema scan and the source-boundary test fail.
  This is P3's arm of section 6's `PARTY-TOKEN-NEVER-TRAVELS` (its item 4,
  "exported database bytes, including the `party_*` tables") — you prove it
  structurally, since no column can hold one.
- **PARTY-INDEX-NOT-PORTABLE** — flip `backup` or `share` to `true` in
  `TABLE_SCOPES` for the new table: the backup/share table-set assertions fail
  and the portable character document changes shape.
- **PARTY-INDEX-NOT-CHARACTER-TRUTH** — serve one character-facing fact (name,
  revision, list membership) from `party_document_states`: the D138 read-model
  test fails. This is P3's slice of `PARTY-OPFS-IS-TRUTH`.
- **PARTY-INDEX-NULLS-STAY-NULL** — give any unproved column a default (`''`,
  `0`, `CURRENT_TIMESTAMP`) or synthesize a last-refreshed time from a failed
  attempt: the D33 absence test and the partial-refresh state test fail. This
  is P3's slice of `PARTY-NO-FALSE-FRESHNESS`.
- **PARTY-PUBLICATION-ID-BRANDED** — widen `PartyPublicationId` to `string` or
  mint it from a `CharacterId`: the type probe fails to compile.
- **PARTY-INDEX-DB-BACKUP-ROUND-TRIP** — drop the table from the restore path
  or from the schema signature: whole-image restore fails. Rows survive a
  database backup/restore; a character backup carries none of them.
- **PARTY-INDEX-CLONE-NO-BINDING** — have an imported character clone inherit
  its source's publication row: the D62 test fails.
