## Scope

1. **The one-line source change.** Add, inside the EXISTING `/*` block in
   `public/_headers` (currently lines 21-32), exactly:

   ```text
     Content-Security-Policy: connect-src 'self' https://api.github.com https://gitlab.com https://codeberg.org
   ```

   Two-space indentation, matching the block. Nothing else in that file
   changes: the `/assets/*` and `/*.wasm` cache blocks, the `/` and
   `/index.html` no-cache blocks, `X-Content-Type-Options`, `Referrer-Policy`,
   `X-Frame-Options`, `Permissions-Policy`, and the commented COOP/COEP lines
   with their explanatory NOTE all survive byte-for-byte. `public/_redirects`
   is not yours.

2. **Prove the line does not break the shipped app before you write it.**
   Enumerate every fetch / XMLHttpRequest / WebSocket / EventSource /
   sendBeacon reachable from the PRODUCTION bundle and state the scheme and
   origin of each. My own grep of `src/` and `tools/pwa/` found exactly three
   call sites — `src/ui/ai-chat/mount.ts:108`, `:191` (dev-only bridge, and
   `tools/assert-dist-clean.mjs` already fails the build if it reaches dist)
   and `tools/pwa/service-worker.ts:117` — but I did NOT audit the SQLite
   wasm loader inside `@sqlite.org/sqlite-wasm`, and `connect-src` governs
   `blob:` and `data:` fetches as well as cross-origin ones. If anything in
   the production graph fetches a non-same-origin, `blob:` or `data:` URL,
   this header breaks production: STOP and report it. Do not widen the
   directive to make a finding go away.

3. **The source half of `PARTY-CSP-CONNECT-SRC`.** A vitest test that reads
   `public/_headers` from disk, parses it into blocks, and asserts against the
   `/*` block: exactly one `Content-Security-Policy` header; its `connect-src`
   source list is exactly the set `'self'`, `https://api.github.com`,
   `https://gitlab.com`, `https://codeberg.org` — set equality, not
   `toContain`; no `*`, no scheme-only source, no host wildcard
   (`https://*.github.com`), no `default-src`/`script-src` smuggled in; and the
   four pre-existing baseline headers are still present.
   **The parser is the load-bearing part, not the assertion.** That block
   contains three comment lines today, two of which are commented-out headers
   (`  # Cross-Origin-Opener-Policy: same-origin`). A parser that treats a
   `#` line as a header reads COOP/COEP as SET — prove it does not, by
   asserting the parsed `/*` block contains no `Cross-Origin-Opener-Policy`
   and no `Cross-Origin-Embedder-Policy` key. A parser that assigns the CSP to
   the wrong block is the other failure mode: assert the CSP is in `/*` and in
   no other block, because Cloudflare applies only matching blocks and a CSP
   under `/assets/*` would never cover the document.

4. **The production-output half.** `_headers` reaches `dist/` by Vite's

## Negative controls (one per load-bearing assertion, name the exact test)

Every one of these must be a mutation you actually apply and watch fail, with
the failing test name pasted:

- Delete `https://api.github.com` from the line → source test fails.
  Delete `https://gitlab.com` → fails. Delete `https://codeberg.org` → fails.
  Three separate runs; section 10 says "deletes each origin in turn".
- Replace an origin with `*` → fails. Replace one with `https://*.github.com`
  → fails (proves it is set equality, not a substring match).
- Delete `'self'` → fails.
- Add a fourth origin (e.g. `https://example.invalid`) → fails, proving the
  assertion is exact rather than a lower bound.
- Move the CSP line out of `/*` into `/assets/*` → fails.
- Uncomment `# Cross-Origin-Opener-Policy: same-origin` → the COOP-absence
  assertion fails; re-comment it and confirm green (this is the parser
  control, and it is the one most likely to be written vacuously).
- Delete the whole `/*` block → fails with a stated "block not found" style
  failure, NOT a vacuous pass over zero headers.
- In the synthetic dist: drop the CSP line from the copied `_headers` →
  scanner exits non-zero. Remove `_headers` entirely → scanner exits non-zero
  with the required-artifact message.
