ARCHITECTURE (non-negotiable):

1. `src/party/controller.ts` is the only place publish/refresh sequencing
   lives. It talks to the storage port, the existing document producer/
   consumer clients, and P3's observation client. It opens no database,
   issues no SQL, constructs no `fetch`, and **never receives a raw token** —
   it takes a lease-bound `PartyStorage` from `createPartyStorage`.
2. Bytes are exactly the D139 document from the SAME shared serializer the
   download path uses (today the literal `JSON.stringify(document, null, 2)`
   at `src/ui/screens/character-list/import-backup-controls.ts:135-145` —
   extract it, do not duplicate it), UTF-8 with a final newline. No envelope,
   no wrapper key, no manifest, no sidecar. Fixed commit messages; never a
   character or library name in a commit message.
3. Read-token-write, section 5's four steps in that order. `write` is called
   only with `replace(expected)` from an exact read, or `create-only` after a
   definite `not-found` with `at: 'object'`. `not-found/unknown` is NOT a
   create licence. No force, no unconditional retry, no last-write-wins.
4. Inbound bytes decode to `unknown` and are discriminated by the document's
   own format name and version before anything touches them. Do NOT copy the
   existing `document as CharacterBackupDocument` cast at
   `import-backup-controls.ts:155` — section 4 forbids that shape for party.
5. Character refresh imports through the D62 importer: a fresh clone, never
   an in-place update of a previously imported character. Library refresh
   goes through DOC-L's D82 plan/commit over CI-2a's resolver (resolution
   order `src/catalog/content-registry.ts:308-343`; collisions throw and roll
   back whole). A remote path that disappeared deletes nothing local — it
   becomes **No longer published**.
6. "Continue publishing this character from this device" is an explicit user
   action binding the local clone to path + just-read revision. Binding is
   never inferred from character name or source database id. The next write
   is still conditional.
7. State is computed-or-absent (D33). The strings are the doc's, verbatim:
   **Unpublished local changes** / **Published at revision N from this
   device** / **Never published**; **Last refreshed successfully: <time>** /
   **Latest refresh attempt: <named failure>** / **Never refreshed**. A null
   timestamp is never formatted as a time; a partial or failed refresh never
   advances the success time; a write whose receipt revision is null yields
   **Published; refresh required before another publish** and blocks the next
   update until an exact read supplies a revision.
8. Conflict presentation is EXTRACTED, not invented: create
   `src/ui/conflict-notice.ts` from the planner's existing shape — the
   structured-data recognition in `#recordError`
   (`src/ui/screens/planner/screen.ts:257-269`) and the `role="alert"` +
   single action link (`src/ui/screens/planner/screen.ts:438-449`) — with a
   closed union `'character-revision' | 'repository-revision'`. Repository
   text: "This party file changed since you refreshed it. Refresh from party
   before trying again."; action "Refresh from party." The planner's command
   refusal semantics must not change by one byte.
9. Partial refresh reports per-file results plus a summary; committed files
   keep their individual receipts, failed files do not. No polling, no
   background write, no service-worker sync, no boot-time forge request.
10. The section 11 licensing acknowledgement is enforced by the controller as
    a call-order precondition of any library write, even though P5 renders it.
11. Remote-derived strings (paths, names, validation excerpts) reach the DOM
    only through `freeTextSpan` (`src/ui/free-text.ts:1-27`); none enters
    structured sheet JSON.
