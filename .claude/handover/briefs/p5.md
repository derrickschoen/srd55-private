## ARCHITECTURE (non-negotiable)

1. **Two routes, two render paths.** Routing is path-based over
   `url.pathname` (`src/ui/router.ts:29-40`); screens are auto-discovered
   modules exporting `screen` with `matches(route)` (`src/ui/app.ts:14-23`;
   shape precedent `src/ui/screens/character-list/screen.ts:7`). Register the
   owner party route and a DISTINCT public-reader route under
   `src/ui/screens/party/`. The public reader is its own `matches` arm and its
   own render path — **not** a boolean flag threaded through the owner screen.
   The exit criterion is proven by ABSENCE of controls, and absence is only
   structurally guaranteed when the code that constructs publish/delete
   controls is unreachable from the public module's import graph. Prove that
   with a source-boundary unit test as well as a DOM test.
2. **The public route holds no credential.** It uses the anonymous vault arm
   (section 6) and an adapter from the exhaustive `createPartyStorage`
   factory. Anonymous readers refresh library documents, review/adopt content
   and import character snapshots as fresh D62 clones; lower rate limits and
   an unreadable private repo are named states, not silent emptiness.
3. **Shared conflict presentation.** Extract `src/ui/conflict-notice.ts` with
   a closed union `character-revision | repository-revision`, consumed by both
   the planner and the party screen. The existing precedent, verified: the
   executor refuses at `src/commands/character-command-executor.ts:193-212,231-254`;
   the Worker transports the current revision as structured error data at
   `src/worker/handlers/commands.ts:46-61`; the planner marks its session
   stale at `src/ui/screens/planner/screen.ts:257-269` and renders "Reload
   this character" at `:438-449`. The extraction may NOT change command
   refusal semantics or the planner's existing text. Repository arm text is
   fixed by section 5: "This party file changed since you refreshed it.
   Refresh from party before trying again." with the single action "Refresh
   from party." No toast, no automatic retry, no retry without a re-read.
4. **Every `StorageResult` arm is a named UI state.** Exhaustive switch, no
   `default:` arm, no `any`, no `@ts-ignore`. Section 9's table IS the
   specification — one rendered state per row, each with its own assertion.
   Nothing collapses into a generic failure. Unknown facts stay visibly absent
   (D33): null `retryAt` renders "Retry time not supplied";
   `not-found/unknown` renders "Repository not found or no longer visible" and
   never a fabricated credential diagnosis; a null post-write revision renders
   "Published; refresh required before another publish", never "up to date".
5. **Freshness and publication states are section 7's, verbatim**: Never
   published / Unpublished local changes / Published at revision N from this
   device / No longer published / Last refreshed successfully: <time> /
   Latest refresh attempt: <named failure> / Never refreshed. A failed or
   partial refresh NEVER advances the success time, and no null timestamp is
   formatted as "just now".
6. **Token UI.** Paste field with the stated session lifetime BEFORE save; a
   connected header showing forge/repository; a labelled, keyboard-operable
   **Forget token** that clears the session entry, invalidates in-memory
   leases, switches the connection to anonymous, and announces the result —
   while leaving OPFS data, repository files and the non-secret repository
   config untouched. P5 itself never touches sessionStorage or a raw token:
   `src/party/credentials.ts` is the only seam, and the screen holds a lease
   handle. The token is never rendered, echoed into a DOM value/attribute,
   placed in a URL, or logged.
7. **Licensing disclosure precedes every library write** (section 11, D59):
   the quoted block plus the included aggregate names and counts, shown before
   the adapter is called. Selected-subset preview is the default action;
   whole-library is an explicit alternative. Call ORDER is load-bearing.
8. **Hostile strings** (D4): every repository-derived string — remote path,
   filename, character name, library label, content name, validation excerpt —
   renders through `freeTextSpan` (`src/ui/free-text.ts:20-27`,
   `FREE_TEXT_MARKER = 'unverified-origin'`). No `innerHTML` with remote data;
   remote prose never reaches the structured sheet JSON.
9. **D108**: labelled controls, keyboard operation throughout, focus trapped
   and restored to the invoking control in the adoption / licensing / conflict
   dialogs (native `<dialog>` + `showModal` precedent at
   `src/ui/screens/planner/items.ts:114-116,181`), status and alert semantics
   never color-only. No WCAG tooling or audit — D108 explicitly excludes it.
   D109: Chromium only.
