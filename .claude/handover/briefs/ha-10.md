## Scope

Every consumer surface that lists or displays catalog content must show
externally published homebrew alongside bundled content, and must DISCLOSE
which layer each entry came from.

D133 IS A NEGATIVE CONSTRAINT HERE, quoted in full: "Full-class authoring
is out of scope ('too much going on') — which the HA design already pinned
(classes bundled-only). Subclass authoring for existing classes stays in
v1." So: species, background, and SUBCLASS pickers gain homebrew entries;
the CLASS picker must remain bundled-only. Pin that negative — a homebrew
row reaching the class picker is a defect, and a test must fail if one
ever does. Quote D133 in your report and state how you satisfied both
halves.

Surfaces in scope (enumerate them yourself from the code; this list is a
floor, not a ceiling):
- guided character creation: species, background, subclass pickers
  (class picker: bundled-only, negative pin)
- level-up wizard: subclass selection at the subclass level
- the character sheet's provenance/disclosure lines
- the build report
- the planner's agent reference
Anything that today reads only bundled tables and would silently omit an
external publication is in scope.

## Rules

- The publisher/catalog layer is the authority for provenance; do not
  re-derive "is this homebrew" from a key prefix at the UI. Read the
  catalog layer.
- Disclosure is honest and specific: an entry says which layer it came
  from, and unknowns SAY unknown (D33). No silent omission, no silent
  inclusion.
- The three authoring forms (HA-7/8/9) and their publishers are DONE —
  consume them, do not fork or modify them.

   rule 2b, including the holder-object pattern for closure-assigned test
   callbacks — TS2349 has broken the build twice.

   its shape and RUN THEM. A self-chosen targeted set that omits the file

   path — homebrew names reach many more surfaces in this unit than in
