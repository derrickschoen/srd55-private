**RECALLED enforcement design:** use ast-grep plus TypeScript nominality, already fitting the repository, before adding ESLint/dependency-cruiser infrastructure. A non-exported runtime class with a private field and exported type alias prevents ordinary structural construction; a single exported builder returns it. Scan tests too, with exact-path exceptions only for deliberate malformed-input/type-negative tests. Avoid banning every object literal: input DTOs and wire values should remain constructible.

**RECALLED important limit:** a `new ClassName(...)` pattern does not resolve aliases, and an import-path rule alone cannot prevent literal fabrication. Test named/aliased/namespace imports, re-exports, dynamic import, `require`, type assertions, `Object.assign`, object spread, `Object.create`, and helper wrappers. A private brand plus removed exports closes ordinary typed routes; explicit casts/reflection can still defeat the type system. An AST/API-surface assertion should also enforce exactly one exported runtime-producing function; an arbitrary `create*` ban is insufficient.

**RECALLED identity contract:** separate immutable policy identity, run identity and mutable state revision. Compute versioned canonical policy digests in builders; bind them into capsules/launchers/persistence and compare them at ingestion. Same digest proves equality of included data, not same object, uniqueness, or equivalent callbacks. A builder called twice with different inputs remains two environments. Compose once per run/process root, thread the value, and use explicit named forks or decode modes where necessary. Never replace this with a module-global mutable environment or a DI service locator.

## 4 Research with sources

**VERIFIED source status:** live web search and primary-page reads performed 2026-09-14. Dates below are publication dates when available; otherwise documentation version or access date. Quotes are operative excerpts, kept below 25 quoted words per source. **RECALLED synthesis:** the requested pattern combines composition root, smart construction/opaque types and architecture enforcement; it is not necessarily the stepwise GoF Builder pattern.

- **VERIFIED — Composition root, Mark Seemann, 2011-07-28:** “A Composition Root is a (preferably) unique location in an application where modules are composed together.” The article places composition near the application entry point and confines container use there. **RECALLED application:** browser, worker and MCP processes have roots; their shared run identity must cross process boundaries explicitly. [Composition Root](https://blog.ploeh.dk/2011/07/28/CompositionRoot/)
- **VERIFIED — Pure DI, Seemann, 2014-06-10:** “Pure DI is Dependency Injection without a DI Container.” He describes containers as optional helpers; the later note distinguishes this term from functional purity. **RECALLED application:** ordinary builder functions and required parameters suffice here; a container does not itself enforce one policy or correct scope. [Pure DI](https://blog.ploeh.dk/2014/06/10/pure-di/)
- **VERIFIED — Haskell smart constructors, GHC 8.10.3 User's Guide §11.7:** “functions that wrap validation around a constructor, and avoid exposing its representation.” The documentation discusses pattern synonyms as a way to retain controlled matching. **RECALLED application:** export the abstract value type and one validating construction boundary, not its representation constructor. [GHC smart-constructor discussion](https://downloads.haskell.org/~ghc/8.10.3/docs/html/users_guide/glasgow_exts.html#pattern-synonyms)
- **VERIFIED — OCaml opaque/abstract types, Real World OCaml online edition, accessed 2026-09-14:** “concrete types let you expose more detail and structure to client code in a lightweight way.” Module signatures hide representations; the chapter explicitly makes abstraction versus concrete structure a contextual choice. **RECALLED application:** opaque runtime contexts; concrete immutable projection/fixture DTOs where all combinations are valid. [Files, Modules, and Programs](https://dev.realworldocaml.org/files-modules-and-programs.html#signatures-and-abstract-types)
- **VERIFIED — F# single-case unions, Scott Wlaschin, 2013-01-13:** “The type `EmailAddress.T` exported by the module signature is opaque, so clients cannot access the internals.” Construction and unwrapping occur at service boundaries. **RECALLED application:** a tiny branded scalar plus a parser can be sufficient; not every ID needs a class hierarchy. [Single case union types](https://fsharpforfunandprofit.com/posts/designing-with-types-single-case-dus/)
- **VERIFIED — Parse, don't validate, Alexis King, 2019-11-05:** “a parser is just a function that consumes less-structured input and produces more-structured output.” Her article also recommends abstract newtypes with smart constructors when structural encoding is impractical. **RECALLED application:** a boolean `verifyEnvironment` leaves the caller holding the untrusted structural input; return the verified branded context instead. [Parse, don't validate](https://lexi-lambda.github.io/blog/2019/11/05/parse-don-t-validate/)
- **VERIFIED — Make illegal states unrepresentable, Wlaschin, 2013-01-14:** “use a union type with a case for each possibility.” The example eliminates the invalid no-contact-address combination. **RECALLED application:** fresh/restore/fixture and legacy/revision-bound inputs should be discriminated unions whose required fields differ by mode. [Making illegal states unrepresentable](https://fsharpforfunandprofit.com/posts/designing-with-types-making-illegal-states-unrepresentable/)
- **VERIFIED — TypeScript nominal compatibility, Handbook, accessed 2026-09-14:** “Private and protected members in a class affect their compatibility.” Compatibility requires private members to originate from the same class. **RECALLED application:** an interface with readonly public fields is structural; a hidden private-field class closes ordinary literal construction. [Type Compatibility](https://www.typescriptlang.org/docs/handbook/type-compatibility)
- **VERIFIED — TypeScript `unique symbol`, Handbook/TS 2.7 feature:** “Each reference to a unique symbol implies a completely unique identity that’s tied to a given declaration.” **RECALLED application:** a non-exported symbol property supplies a lightweight brand; an assertion can bypass it, and an erased brand is not runtime validation. [Symbols](https://www.typescriptlang.org/docs/handbook/symbols)
- **VERIFIED — JavaScript private fields, TypeScript 3.8:** “Every private field name is uniquely scoped to its containing class.” The release notes distinguish erased TypeScript `private` from runtime `#` fields. **RECALLED application:** use a real private field for the approved runtime representation; still validate incoming JSON and do not claim protection against arbitrary casts/reflection. [TypeScript 3.8](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-3-8.html)
- **VERIFIED — TS newtype idiom, `gcanti/newtype-ts` README (0.3 compatibility table, accessed 2026-09-14):** “a value of type `EUR` is just a `number` at runtime.” It uses a `unique symbol` marker and distinguishes wrapping from predicate-based refinements. **RECALLED application:** borrow the type technique; do not add the package or confuse `iso.wrap` with validation. [newtype-ts](https://github.com/gcanti/newtype-ts)
- **VERIFIED — ESLint `no-restricted-imports`, current docs (introduced v2.0.0-alpha-1), accessed 2026-09-14:** “It applies to static imports only, not dynamic ones.” Paths, patterns and named imports can be restricted; re-exports are covered as documented. **RECALLED application:** useful if ESLint is adopted, but not sufficient for literal/cast construction or dynamic import paths. [no-restricted-imports](https://eslint.org/docs/latest/rules/no-restricted-imports)
- **VERIFIED — `import/no-internal-modules`, plugin main docs, accessed 2026-09-14:** “Use this rule to prevent importing the submodules of other modules.” It supports allow or forbid glob lists. **RECALLED application:** protects public module entry points, not object validity or same-run identity. [Rule documentation](https://github.com/import-js/eslint-plugin-import/blob/main/docs/rules/no-internal-modules.md)
- **VERIFIED — dependency-cruiser main rules reference, accessed 2026-09-14:** “A list of rules that describe dependencies that are not allowed.” Its `forbidden` rules operate on dependency relationships, including supported reachability checks. **RECALLED application:** add it if resolved/transitive import boundaries become necessary; it cannot prove a literal's policy digest or lifetime. [Rules reference](https://github.com/sverweij/dependency-cruiser/blob/main/doc/rules-reference.md)
- **VERIFIED — ast-grep configuration and CLI docs, accessed 2026-09-14; installed binary 0.40.5:** “Paths in `files` are relative to the project root directory, that is, `sgconfig.yml`'s directory.” Rule globs filter only files the CLI visits; ignores and language choice still matter. **RECALLED application:** expanding the scan path is essential; add checked syntax fixtures and verify compatibility with the installed binary rather than assuming current docs equal its feature set. [Rule configuration](https://ast-grep.github.io/reference/yaml), [Rule testing](https://ast-grep.github.io/reference/cli/test.html)
