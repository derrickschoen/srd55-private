## Findings

1. **P1 — X2 contains an observable wrong value while claiming exact output.** The proposed replacement of aggregate `interveningCells` with `[]` changes a field returned by `traceTerrainLine` and `traceCombatantLine` ([cover.ts:145–156](/home/vagrant/PhpstormProjects/dnd-multiclass-spells-static/src/combat/cover.ts:145), [359–374](/home/vagrant/PhpstormProjects/dnd-multiclass-spells-static/src/combat/cover.ts:359)). Existing tests mostly inspect per-line cells, so a digest of selected heavy files could miss it. **Fix:** retain the computed field for this equivalence experiment. If removing it is desirable, make that a separately reviewed API change that removes the field from the type and audits consumers; do not return a plausible empty value.

2. **P1 — X3’s stated byte-level acceptance check cannot pass unchanged.** Readiness spools contain timestamps from `Date.now()` ([entrypoint.ts:720–725](/home/vagrant/PhpstormProjects/dnd-multiclass-spells-static/src/vtt/mcp/entrypoint.ts:720), [760](/home/vagrant/PhpstormProjects/dnd-multiclass-spells-static/src/vtt/mcp/entrypoint.ts:760)). **Fix:** control the clock in both child runs, or specify a narrow, proved normalization of only those timestamp fields. Compare exit status and stderr as well as stdout and every spool; add a deliberately wrong response to show the comparison fails.

3. **P2 — X3 has an incomplete launcher inventory and an unproved Vite-equivalence recipe.** The real adapter’s `engineArgs` bypass `startMcpClient` ([ai-dm-conversation.ts:4321–4328](/home/vagrant/PhpstormProjects/dnd-multiclass-spells-static/tools/ai-dm-conversation.ts:4321)). The graph’s `?raw` corpus and mode-dependent parse cache require deliberate esbuild loaders and defines. **Fix:** list and count each child-launch site, state which the experiment changes, and compare each selected mode’s startup, request responses, spools, failures, and environment. Hash the complete build input graph and include bundle-build time in gate wall.

4. **P2 — X1’s proof must cover callback behavior and an independent oracle.** The in-memory differential is strong preliminary evidence, but the proposed test names `isGoal` without `rank`; [movement-evaluator.ts:497](/home/vagrant/PhpstormProjects/dnd-multiclass-spells-static/src/combat/movement-evaluator.ts:497) and [engine-query-port.ts:1165](/home/vagrant/PhpstormProjects/dnd-multiclass-spells-static/src/vtt/engine-query-port.ts:1165) exercise different search forms. The existing blind parity “expected” map calls the same query port ([blind-turn-context.test.ts:157–171](/home/vagrant/PhpstormProjects/dnd-multiclass-spells-static/tests/unit/vtt/blind-turn-context.test.ts:157)). **Fix:** compare against an uncached path implementation and clean-main byte pins captured before patching; include `rank` order, mixed calls, exceptions, and a named wrong-path or wrong-cost mutant that the controls kill.

5. **P2 — State identity is a cache-validity contract that the plan has not established.** `readonly` is erased at runtime, and the new search and memo pack add more long-lived results to existing state-keyed caches. **Fix:** document the state lifecycle and prove that callers replace rather than mutate queried snapshots, then exercise an audit that detects stale values. A mutation-after-query test should either be rejected explicitly by the contract or demonstrate correct invalidation.

6. **P2 — The trial cannot yet attribute or reliably accept gains.** R0 runs first, candidate arms follow sequentially, and two measured runs are small relative to observed initial and retry variation. “Compare the red set with R0” also becomes invalid when X4 intentionally fixes the docs failures. **Fix:** use the gate’s initial phase as the initial metric, run matched alternating baseline/candidate pairs on fixed commits and comparable cache state, record load and invalid-pair criteria, and compare each phase’s failures against an explicit expected set. Keep X4 as its own before/after contrast. Define a minimum saving and uncertainty rule before seeing results.

7. **P2 — The preservation inventory is too narrow for the proposed test optimizations.** File and test counts can remain equal while a room generator, database seeder, or board-mode assertion stops exercising its subject. The [room test](/home/vagrant/PhpstormProjects/dnd-multiclass-spells-static/tests/unit/vtt/room-generator-los-cover.test.ts:264) currently regenerates each pinned fixture, and [D306](/home/vagrant/PhpstormProjects/dnd-multiclass-spells-static/.claude/decisions.md:106) restricts seeded database-image optimization. **Fix:** carry the planner’s fresh second-generation and first-correct-then-wrong controls into X5; require per-test cloned database images through the permitted helper with image equivalence; prove both board modes still execute their distinct claims. Check changed outputs with named wrong-value mutants, not counts alone.

8. **P2 — X6’s shuffle guard needs an executable test, and its benefit may vanish after X1.** Vitest keeps a configured sequencer when `--sequence.shuffle` is requested ([coverage.DM_a_rWm.js:470–477](/home/vagrant/PhpstormProjects/dnd-multiclass-spells-static/node_modules/vitest/dist/chunks/coverage.DM_a_rWm.js:470)). Merely checking that the sequencer returns a permutation does not prove shuffled file order. **Fix:** assert two seeds produce different file orders under `npm run test:shuffled`, and retain X6’s conditional “hidden setup still ends last” entry criterion.

9. **P2 — The model and role rulings need revision before dispatch.** The 459-second floor applies to the old workload; the model must be recalibrated after CPU removal. Also, the recorded [D860 ruling](/home/vagrant/PhpstormProjects/dnd-multiclass-spells-static/.claude/decisions.md:1488) specifies `gpt-5.6-sol` at the prior review effort, while §7 specifies `gpt-6-sol` xhigh and promises a later D879 exception. **Fix:** label model projections as historical until measured again, and record the specific owner authorization for the §7 model exception before using it, or follow D860.

10. **P3 — Separate measurements from product claims and budget claims.** X3 may chiefly accelerate simulated test children until the other launchers are addressed. The estimate of “11–15 full runs at 10–13 minutes” is optimistic against the four observed real-gate walls of 881–1,254 seconds, before separate baseline or prewarm runs. **Fix:** report per-arm initial, retry, bundle-build, and total wall, plus the child count actually converted; budget box time from real-gate totals.

## Verdict

**REVISE.** X1 has a credible measured lead, but the plan currently includes an output-changing X2 patch and an impossible literal X3 byte check. Resolve those, establish independent wrong-value controls, and tighten the gate comparisons before running acceptance experiments.
