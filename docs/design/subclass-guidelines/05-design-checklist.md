Purpose: provide one mandatory pre-flight that turns a complete subclass draft into an auditable playtest candidate.

# Subclass design pre-flight

Run this checklist on the full subclass attached to the full parent chassis. Fill the evidence blank after every item. `Pass` requires a rule, calculation, SRD comparison, or simulation result; confidence alone is not evidence. A failed item triggers revision. An unknown item is marked provisional in the review packet.

## 3. Progression and scaling

- [ ] **Level-3 loop present.** At level 3, the player can observe, choose, act, and create the advertised change. It is neither a preview nor the subclass's final power peak. (`03-fun-and-memorability.md` — **Establish the identity loop at level 3**) Evidence: ___
- [ ] **Later features deepen the loop.** Each later slot improves reliability, expression, scope, action cost, or tier-appropriate consequence. Unrelated widgets and a second resource system are removed. Evidence: ___
- [ ] **Tier-appropriate scaling.** Test at levels 5, 11, and 17. Entry numbers neither decay into decoration nor multiply through attacks or targets. Tier 3 adds a verb or action improvement; tier 4 is decisive and simple. (`01-power-budget.md` heuristics 1 and 4; `03-fun-and-memorability.md` — **Grow with the tiers**) Evidence: ___
- [ ] **Native-engine attachment.** Scaling uses host-class level or the parent engine where practical. A subclass-only pool exists only when the fantasy cannot be expressed with native currency. (`02-cadence-and-anatomy.md` — **Scaling attaches to the parent engine**) Evidence: ___
- [ ] **No new required ability.** Every attack, DC, use count, or scaling value uses an ability the base class already advances, the class DC, or host-class level. (`01-power-budget.md` heuristic 12) Evidence: ___

## 4. Multiclass and interaction audit

- [ ] **Full-stack test.** Evaluate each combat feature with ordinary tier equipment, advantage, party support, class riders, and the strongest legal same-class turn. ## 6. Resource and rest stress

- [ ] **Uses model matches effect.** At-will effects are modest; multi-use Long Rest pools produce repeated decisions; Short Rest recovery is a top-up rather than a dependency; a one-use showpiece is not the sole identity loop. (`01-power-budget.md` heuristic 9; `02-cadence-and-anatomy.md` — **Resource-costing shapes**) Evidence: ___
- [ ] **One-fight-day test.** Spend every compatible resource in the shortest legal encounter. Record the best round, target count, control duration, and defensive swing. The nova does not invalidate the host's same-tier baseline. (`04-failure-taxonomy.md` — **F10. The White-Room Day**) Evidence: ___
- [ ] **No-Short-Rest-day test.** Run several encounters with no Short Rest. The subclass still performs its loop and does not become a spectator. Evidence: ___
- [ ] **Rest-rich-day test.** Apply every permitted recovery. Repeated Short Rests or native-currency reloads do not create unlimited output. Evidence: ___
- [ ] **Drawback integrity.** No cost can be erased through spare equipment, target choice, inventory swapping, or procedural setup. One failure never produces several punishments. (`04-failure-taxonomy.md` — **F1. Compounding Punishment** and **Inventory-neutralized drawbacks are not drawbacks**) Evidence: ___

### Pre-flight result

- **Ready for playtest:** structural and clean-room checks pass; remaining unknowns are explicitly provisional and testable.
- **Ready for design review only:** one or more mechanical or social checks lack evidence, but the draft is complete enough to critique.
- **Not ready:** schedule, level-3 loop, clean-room boundary, action economy, or adjudication text fails. Revise before circulation.
